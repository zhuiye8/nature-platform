## 2. 质量审核

### 已确认规则

| 规则 | 结论 | 确认日期 |
|------|------|---------|
| 驳回时是否必须填写原因 | **必填**（wf_task.remark NOT NULL on REJECT） | 2026-03-23 |
| 驳回后现场测评数据是否清空 | **不清空**，保留修改，测评师在原有基础上修正 | 2026-03-23 |
| 一个用户能否同时是 PM 和技术审核 | **可以**（不同项目可以，同项目内通过回避机制处理） | 2026-03-23 |
| 同一用户同一项目能否既是 PM 又是审核人 | **不可以**（回避规则 SAME_PROJECT 自动排除） | 2026-03-23 |

### 回避算法

```
输入：node_key, slot_key, project_id
输出：assignee_id（选中的审核人）

步骤：
1. 读取 wf_assignment_rule WHERE node_key AND slot_key，按 priority ASC 排序
2. 对每条规则，读取该 role_code 的所有用户（按 user_role.sort_order ASC）
3. 如果 avoidance_rule = 'SAME_PROJECT'：
   → 读取 project_member WHERE project_id AND status='ACTIVE' → 回避名单
   → 从用户列表中排除回避名单
4. 取排除后的第一个用户
5. 如果当前角色无可用人选，尝试下一条规则（更低优先级的角色）
6. 全部规则都无人可选 → 返回 null，前端提示管理员手动指定
```
