### 第 8 步：现场测评（多人协作 + 文件池）

| 项目 | 说明 |
|------|------|
| **操作人** | 项目组全体成员 |
| **菜单** | 现场测评 → 点击项目「查看」 |

**文件池说明**（Batch 3 新增）：

| 文件池 | 上传权限 | 说明 |
|--------|---------|------|
| 测评文件 | 全体项目成员 | 测评过程中的原始文件 |
| 测评成果 | 仅项目经理 | 最终提交审核的成果物 |

**操作流程**：
1. 测评师上传测评文件到「测评文件」池
2. 项目经理整理后上传到「测评成果」池
3. 项目经理点击「发起质量审核」

---

### 第 9 步：技术审核（通过/复核）

| 项目 | 说明 |
|------|------|
| **操作人** | 自动分配（回避项目组成员） |
| **菜单** | 待办中心 → 审核任务 |
| **操作** | 点击「审核」→ 查看测评成果 → 选择操作 |

**候选审核人**：`chengang`（陈刚）、`hujssh`（胡技术审核）、`wangli`（王丽，但在项目组时被回避）

**三种操作**（Batch 1-2 新增）：

| 操作 | 效果 | 后续 |
|------|------|------|
| **通过** | 填写审核意见 → 推进到内容审核 | 意见记录到 review_opinion |
| **复核** | 填写复核意见 → 任务变为「待整改」 | 通知项目经理整改 |

**复核闭环**（Batch 2 新增）：
1. 审核人点「复核」→ 填写整改意见 → 任务状态变为 PENDING_RECTIFICATION
2. 项目经理收到通知 → 在「现场测评详情」页看到"待整改"标签
3. 项目经理修改测评成果后点「重新提交」
4. 审核人收到通知 → 任务重置为 PENDING → 重新审核
5. 循环直到通过

| 项目 | 说明 |
|------|------|
| **操作人** | 自动分配三人（回避项目组成员） |
| **菜单** | 待办中心 → 审核任务 |

**自动分配**：

| 审核项 | 角色 | 候选人 |
|--------|------|--------|
| 内容审核（技术） | content_reviewer_tech | `chengang`、`zhaoliu`（项目组时回避）、`henrjs` |
| 内容审核（管理） | content_reviewer_mgmt | `wangfang`、`sunming`、`magl` |

**特殊规则**：任一人选择「复核」→ 该节点**全部三人**的任务都变为 PENDING_RECTIFICATION → 项目经理重新提交后三人全部重新审核

- **全部通过** → 进入报告编制
- **任一驳回** → 回到现场测评

### 第 12 步：最终审核（通过/复核/驳回）

| 项目 | 说明 |
|------|------|
| **操作人** | `jingli`（赵经理）、`wangjl`（王经理）或 `admin` |
| **菜单** | 待办中心 → 审核任务 |
| **操作** | 审核报告 → 查看测评成果和编制报告文件 → 选择操作 |

**三种操作**：

| 操作 | 效果 | 后续 |
|------|------|------|
| **通过** | 填写审核意见 → 推进到材料归档 | 项目接近完成 |
| **复核** | 填写复核意见 → 待整改 | PM 修改后重新提交 → 重新审核（同技术审核闭环） |
| **驳回** | 填写驳回理由 → 轮次 +1 → 回到技术审核 | 技术审核 → 内容审核 → 报告编制 → 最终审核（全部重新走） |

**注意**：「调整」操作仍然保留用于非质量审核路径（调整 → 回到现场测评 → 跳过技术/内容审核 → 直接到报告编制）

## 驳回/复核/调整路径汇总

| 节点 | 操作 | 后续 |
|------|------|------|
| 合同审核 | 驳回 | 销售编辑合同 → 重新提交 → 合同审核 |
| 项目审核 | 驳回 | 创建人编辑项目 → 重新提交 → 项目审核 |
| 技术审核 | 复核 | PM 修改测评成果 → 重新提交 → 技术审核（当前节点内循环） |
| 内容审核 | 复核（任一人） | 全部三人待整改 → PM 重新提交 → 全部三人重审 |
| 最终审核 | 复核 | PM 修改 → 重新提交 → 最终审核（当前节点内循环） |
| 最终审核 | 驳回 | 轮次 +1 → 回到技术审核 → 内容审核 → 报告编制 → 最终审核 |
| 最终审核 | 调整 | 回到现场测评 → PM 重新提交 → **跳过技术/内容** → 报告编制 → 最终审核 |

## 审核意见历史

质量审核流程中每次操作（通过/复核/驳回/重新提交）都会记录到 `review_opinion` 表。

**查看方式**：
- **审核人**：在任务详情页的「审核意见历史」区域查看
- **项目经理**：在现场测评详情页的「审核意见历史」区域查看

意见按轮次（round_no）分组展示，可追溯每一轮的审核过程。

## 通知机制

| 事件 | 通知对象 | 通知内容 |
|------|---------|---------|
| 新任务创建 | 任务指派人/池内用户 | "你有新的待办任务：XXX" |
| 审核人选择「复核」 | 项目经理 | "XXX节点需要整改" |
| PM 重新提交 | 原审核人 | "整改已重新提交，请重新审核" |
| 审核通过 | 业务创建人 | "审核已通过" |
| 审核驳回 | 业务创建人 | "被驳回：原因" |
