## 五、已知预期行为（不算 bug）

| 现象 | 是否预期 | 解释 |
|---|---|---|
| 销售看不到别人的合同 | ✅ 预期 | 数据可见性设计：sales 只看自己创建/负责的 |
| 项目登记未通过的合同选系统时显示"无可选系统" | ✅ 预期 | 必须 `system_no` 非空（即项目登记审批通过） |

| chairman 看不到 super_admin 才有的某些底层操作 | ✅ 预期 | chairman 不是 super_admin |
| 销售看不到 chairman 类菜单（用户/角色等） | ✅ 预期 | 默认 sales 没有这些权限 |

如果测试合同（如 #2）的回款/开票数据被污染想重置，可联系开发执行：

```sql
-- 仅清理本批测试数据（保留合同本身）
DELETE FROM finance_invoice_application_system
  WHERE invoice_application_id IN (
    SELECT id FROM finance_invoice_application WHERE contract_id = 2
  );
DELETE FROM finance_invoice_application WHERE contract_id = 2;
DELETE FROM contract_payment_record WHERE contract_id = 2;
UPDATE contract SET payment_status = 'UNPAID' WHERE id = 2;
```

## 附录 A · 主要变更点

### A.1 新增页面
- `/finance/contract/:id` - 合同财务详情页（新建）
- `/finance/invoice` - 开票申请列表（新建）
- `/finance/invoice/create` - 新建开票申请
- `/finance/invoice/:id` - 开票申请详情/审核
- `/finance/invoice/:id/edit` - 编辑开票申请

### A.2 数据库变更
- `project_system_item` 新增 `amount` 字段
- 新表 `contract_payment_record`（回款明细）
- 新表 `finance_invoice_application`（开票申请）
- 新表 `finance_invoice_application_system`（开票-系统关联）

### A.3 角色变更
- 新增 `chairman` 角色（董事长）
  - 业务全只读
  - 系统管理全权
  - 待办看不能操作
- 已分配给：`ceshi`（测试用户，本地）

### A.4 权限新增
- `invoice:apply` - 发起开票申请（所有非超管角色都有）
- `invoice:list` - 查看开票申请列表
- `invoice:review` - 审核开票申请（财务）
- `payment:record` - 录入回款记录（财务）

### A.5 工作流新增
- `FIN_INVOICE`（开票申请流程）
  - 节点：`FIN_INVOICE_REVIEW`（财务审核）
  - 转换：APPROVE → 已开票，REJECT → 需修改
  - 分配：finance（兜底 super_admin）
