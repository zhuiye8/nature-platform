## 调研规则（每个维度文档都遵守）

### 1. 输出格式
```markdown
# 维度 X · [维度名]

> 扫描时间、范围、发现总数

## 扫描清单（务必勾选）
- [x] 文件 1（已扫）
- [x] 文件 2（已扫）
- [ ] 文件 N（**未能扫描，原因：xxx**）

## 🔴 P0 严重（n 条）
### F1.1 · 一句话标题
- 位置：file:line
- 现象：...
- 影响：...
- 修复：...

## 🟡 P1 应改 / 🟢 P2 待优化
（同上格式）

## 备注
- 已知预期行为（不算 bug 的）
- 跨维度可能涉及的（写明可能与维度 X 重复）
```

### 2. 质量要求
- ✅ 文件:行号必须准确（用 Read 查证）
- ✅ 每个 finding 必须有具体的修复建议（不能"应该改"了之）
- ✅ 优先级有依据（P0=数据丢失/权限漏洞/严重 bug，P1=用户体验/隐患，P2=优化）
- ✅ 不模糊、不臆测、不看到 X 就说 X 一定有问题

### 3. 边界规则
- 各维度互不交叉，但发现的问题如果跨维度可标注（如"也涉及维度 5"）
- 扫描清单里的文件必须全部 ✅ 标记，未扫的必须解释原因
- 不抄袭其他 agent 的发现（每个 agent 独立扫）
